# Как работать со средой проекта TRPG

Короткая методичка: что у нас настроено, как формулировать задачи, чтобы всё
подхватывалось само, и что делать, когда что-то идёт не так.

---

## 1. Что вообще настроено

Среда — это набор файлов, которые Claude читает сам. Тебе не нужно их пересказывать
в каждом запросе.

| Что | Где лежит | Когда читается |
|---|---|---|
| **CLAUDE.md** | корень проекта | всегда, автоматически |
| **PLAN.md** | корень проекта | в начале сессии — где мы сейчас и что дальше |
| **Скилы проекта** | `.claude/skills/trpg-*` | сами, когда задача попадает в их тему |
| **Агент ревью** | `.claude/agents/trpg-product-review.md` | только когда позовёшь явно |
| **Дизайн-движок** | `~/.claude/` (агенты + скилы) | в любом проекте, по теме задачи |
| **Память** | `~/.claude/projects/.../memory/` | сама, по смыслу разговора |

**Пять скилов проекта** и за что отвечают:

- **trpg-workflow** — вход в любую задачу: процесс, коммиты, грабли, дерево файлов.
- **trpg-ui** — дизайн-система: цвета, шрифты, отступы, скругления, анимации, хаптика.
- **trpg-supabase** — база: SQL, RPC, RLS, миграции, Edge Functions.
- **trpg-ds-review** — страж целостности ДС: зовётся ПЕРЕД правкой интерфейса.
- **trpg-figma** — перенос и синк проекта в Figma.

Тебе **не надо** их вызывать руками. Claude подбирает нужные сам по словам в задаче.

---

## 2. Как формулировать задачи

Главное правило: **скажи, что не так или что нужно, — своими словами.**
Не нужно называть файлы, скилы или технологии.

### Работает само

| Ты говоришь | Что подхватится |
|---|---|
| «на главной кнопка съехала» | trpg-ui + trpg-ds-review |
| «добавь поле для веса тела» | trpg-workflow + trpg-supabase + trpg-ui |
| «данные не сохраняются» | trpg-supabase |
| «нарисуй этот экран в Figma» | trpg-figma |
| «покажи, что в базе у пользователя 22» | коннектор Supabase |
| «посмотри ошибки в Sentry» | коннектор Sentry |
| «проверь, как это выглядит в браузере» | Playwright (кликает) или Chrome DevTools (диагностика) |

### Полезные уточнения

- **«проверь глазами»** — Claude поднимет `npm run dev`, откроет экран в браузере
  и посмотрит на результат, а не сдаст «по коду».
- **«покажи сначала план»** — когда правка большая и хочешь понять, что будет.
- **«не коммить пока»** — по умолчанию он коммитит и пушит сам, когда всё зелёное.
- **«запиши это в скил»** — превратит договорённость в постоянное правило.
- **«обнови PLAN.md»** — если он забыл это сделать сам.

### Когда звать агента ревью

`@agent-trpg-product-review` — честное UX-ревью экрана или сценария. Он **не меняет код**,
а возвращает список правок. Полезно перед тем, как что-то переделывать.
Не путать с `trpg-ds-review` — тот про токены и консистентность, этот про удобство.

## 3. Что происходит после твоей правки

Каждый раз, когда меняется код, порядок один:

```
правка → npm run lint → npm test → npm run build → коммит в main → git push
```

Все три проверки должны быть зелёными. Ты это увидишь в ответе: **✅** значит всё прошло.
Пуш — сразу, руками в GitHub Desktop нажимать ничего не нужно. Дальше Timeweb
сам выкатит новую версию на `trpg1.ru`.

**База — отдельно.** Миграции применяются через коннектор Supabase вручную, и на
изменения политик доступа система может спросить у тебя подтверждение — это нормально,
так и задумано.

**Edge Functions — тоже отдельно.** Правка в репозитории НЕ означает правку в бою,
их деплоят руками. Их три, и все три про вход в приложение.

## 4. Если что-то пошло не так

| Ситуация | Что сказать |
|---|---|
| Сломалось после правки | «откати последний коммит» |
| Не понял, что он сделал | «объясни простыми словами, что изменилось» |
| Слишком много текста в ответе | «короче, только результат» |
| Полез не туда | «стоп, сначала обсудим» |
| Забыл про наше правило | «это уже обсуждали, посмотри в скилах» |
| Хочу вернуть удалённый файл | «верни файл X из гита» — история хранит всё |

Откатить можно почти всё: код лежит в гите, база бэкапится каждый день в 05:00.

## 5. Что среда делает без тебя

- **GitHub Actions**: проверка сборки на каждый push · бэкап базы ежедневно ·
  keepalive базы дважды в неделю · напоминания и итоги в Telegram по 5 расписаниям.
- **Падение любой из этих задач приходит тебе в Telegram.** Тишина = всё хорошо.
- **Sentry** ловит ошибки у живых пользователей, теперь с меткой, кто именно словил.

## 6. Правила гигиены среды

Чтобы она не сгнила за пару месяцев:

1. **Появилось устойчивое правило — сразу в скил.** Скажи «запиши это». Договорённость,
   не попавшая в файл, забудется к следующей сессии.
2. **Разовая деталь — не в скил.** Скилы висят в контексте постоянно; чем их больше
   и толще, тем хуже они срабатывают.
3. **Удалил что-то — проверь ссылки.** Именно так у нас четыре агента ссылались на
   удалённый скил, а вся четвёрка — на несуществующий гайд.
4. **PLAN.md обновляется по итогам работы**, а не «когда-нибудь».
5. **Раз в пару месяцев** говори: «проверь скилы» — Claude прогонит аудит: битый YAML,
   мёртвые ссылки, дубли, разросшиеся файлы.

## 7. Короткая шпаргалка

```
Начать работу        → просто опиши задачу своими словами
Проверить глазами    → «проверь в браузере»
Большая переделка    → «покажи сначала план»
UX-ревью экрана      → «@agent-trpg-product-review посмотри экран дня»
Запомнить правило    → «запиши это в скил»
Что сейчас в работе  → «посмотри PLAN.md»
Порядок в среде      → «проверь скилы»
Откат                → «откати последний коммит»
```
