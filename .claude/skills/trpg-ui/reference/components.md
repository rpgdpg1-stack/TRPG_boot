# TRPG UI — компоненты

Справочник компонентов дизайн-системы. Ядро правил (токены, цвета, отступы) — в `SKILL.md`.

## Икон-кнопки (круглые)

Кнопки-иконки одного семейства (добавить `+` / убрать `✓` / удалить `✕` / закрыть `✕`) держим
**одного размера и формы** во всех экранах, чтобы читались как одна кнопка:
- `36×36`, `borderRadius: 50%`, глиф `fontSize: 18px / fontWeight: 700`.
- Центрировать символ через `display:flex` + `alignItems/justifyContent: center` + `lineHeight: 1`.
  Текстовые глифы (`✕`/`+`/`✓`) сидят не по оптическому центру — добавлять доводчик `paddingBottom: 1–2px`.
  Надёжнее рисовать глиф как inline-SVG (как `GripIcon` в конструкторе) — тогда центр геометрически точный
  без подбора пикселей.
- **Неактив — нейтральный**: серый фон `rgba(255,255,255,0.06)` + `--color-text-secondary`.
  Акцентный цвет (зелёный) — только для активного/подтверждённого (выбранная галочка `✓`).
  Не заливать неактивную кнопку ярким `--color-primary`.
Эталон — кнопка `+/✓` в `ExercisePicker`; к ней приведены крестик удаления в `ProgramConstructor`
и крестик-очистка поиска (последний крупнее — 44px, т.к. часть поля поиска).


## Карточка упражнения

Единый вид строки-упражнения. Базовые размеры одинаковы на всех трёх экранах — различается только
правая зона и левый край.

**База (эталон — экран смены `SwapExercise.jsx`):**
- Контейнер: `flex; alignItems:center; gap:12px; padding:12px; minHeight:90px;`
  `background: var(--color-card); borderRadius: var(--radius-card)`.
- Превью: `64×64`, `var(--radius-medium)`, белый фон, `objectFit:cover`;
  плейсхолдер-эмодзи `fontSize:28px; opacity:0.4`.
- Контент: колонка, `gap:5px`.
- Имя: `var(--font-geist)` `13px / 700 / lineHeight:16px`, перенос разрешён (без ellipsis).
- Тег: `10px / 700`, `borderRadius:999px`, `letterSpacing:0.2px; lineHeight:13px`. **Один тег —
  подгруппа** (`SUB_GROUP_LABELS`, фолбэк на имя группы) в цвете **основной** группы
  (`getMuscleGroupColors().tag`, белый текст), **`opacity: 0.7`** (спокойный, приглушённый вид). Имя
  группы (Спина/Грудь) не дублируем — оно в заголовке секции. **Правило единое ВЕЗДЕ, где есть тег
  упражнения:** `ExerciseCard`, `ExercisePicker` (строки списка), `SwapExercise`, `ProgramConstructor`,
  а также **`ExerciseActionMenu`** (долгий тап) и **`ExerciseHeaderCard`** (техника упражнения) — в этих
  двух РАНЬШЕ было два чипа (группа+подгруппа), теперь ТОЛЬКО подгруппа в цвете группы, `opacity 0.7`.
  Чипы групп дня в шапке (`WorkoutDay.dayChips`) — тоже `opacity 0.7`.
- **Цвет числа веса — БЕЛЫЙ** (`--color-text`, тот же, что заголовок упражнения) — **ВЕЗДЕ, где
  выводится вес**: `ExerciseCard`, `ExerciseActionMenu`, страница `/favorite-exercises`, список любимых
  в модалке профиля (`ProfileMetrics`) и крупное число в `WeightProgressModal` (сама ЛИНИЯ графика там
  остаётся в цвете группы). Проба Дмитрия (август 2026) вместо прежнего акцентного цвета группы: цвет
  группы остался на теге/заголовке, число перестало пестрить. Каретка ввода — по-прежнему в цвете
  группы (`colors.accent`).
  Изменение веса (blur/Enter) → КОРОТКАЯ вспышка ~2с, затем цвет
  возвращается к базовому: ПОВЫШЕНИЕ (новое > старого) → зелёная стрелка ↑ + зелёное число
  (`--color-primary`, keyframes `weightRaiseArrow` с лёгким подъёмом); ПОНИЖЕНИЕ (новое < старого) →
  стрелка ↓ + число в фиксированном сером (`WEIGHT_DOWN_COLOR` #B0B0B0 — ярче приглушённого текста, но
  не белый), keyframes `weightLowerArrow` — **зеркало `weightRaiseArrow`**: стрелка приезжает сверху
  (`-50% - 4px` → `-50%`) и останавливается, ход у обеих один. Равный/0 — без вспышки,
  красного нет. Ничего не хранится. Общий хук `useWeightRaiseFlash()` в `components/WeightRaiseFlash.jsx`:
  `trigger('up'|'down')`, `colorFor(accent)` (цвет числа с учётом вспышки), `arrow`. Применяется в
  `ExerciseCard` и `ExerciseActionMenu`.
- **Фильтр-чипы в пикере (`ExercisePicker`) — НЕ теги, свои правила, БЕЗ opacity (яркие):** верхний ряд
  групп — активный чип залит цветом СВОЕЙ группы (`getMuscleGroupColors(group).tag`, белый текст);
  ряд подгрупп активной группы — активная подгруппа тоже заливается **цветом группы** (`.tag`), НЕ общим
  зелёным. Неактивные — серый фон + `--color-text-secondary`.

**Заголовков групп мышц в проекте НЕТ (август 2026).** Ни на дне тренировки, ни в конструкторе, ни
в «Любимых», ни в модалке профиля — списки сплошные, с одинаковым шагом между карточками.
Принадлежность упражнения несёт **ТЕГ внутри карточки**: `«Группа — Подгруппа»` («Ноги — Квадрицепс»),
обычным регистром, в цвете группы (`getMuscleGroupColors().tag`, `opacity 0.7`).

Подпись собирает **один помощник — `exerciseTagLabel(muscleGroup, subGroup)`** (`features/programs/
labels.js`). Своими руками не склеивать: там же живёт правило «группа = подгруппа → пишем одно слово»
(«Бицепс», а не «Бицепс — Бицепс»). Применён в `ExerciseCard`, `ExerciseActionMenu`,
`/favorite-exercises`, списке любимых в профиле (`ProfileMetrics`), конструкторе и в личных рекордах.

Где тег НЕ на первой строке (список любимых в профиле, рекорды) — он идёт **второй строкой под
названием** упражнения, пилюлей того же вида. Исключения по смыслу: `ExercisePicker` и `SwapExercise`
показывают только подгруппу — там группа уже задана контекстом (фильтр по группе / замена внутри
одной подгруппы), и полный тег дублировал бы одно и то же в каждой строке.

**Свайп влево по карточке (`ExerciseCard`)** — панель действий справа: **ТОЛЬКО «Техника» и «Замена»**
(`SWIPE_PANEL_W = 116`, по 58 на действие). «Заметка» из свайпа УБРАНА — она живёт в меню по долгому
нажатию, где текст можно сразу написать, а не открывать ещё один экран. Геометрия панели — из двух
констант (`SWIPE_GAP` 8 + `SWIPE_CELL` 50), ширина считается сама:
`SWIPE_GAP + N*(SWIPE_CELL+SWIPE_GAP)`. **Зазор ОДИН и тот же** — от края карточки до первой плитки,
между плитками и до правого края; раньше первая плитка липла к карточке вдвое ближе, чем плитки
друг к другу. Добавляешь действие — правится только список (**грабля:** ширина и выделение были
зашиты под три действия — после удаления «Заметки» подсветка встала мимо кнопок).

**Экран замены (`SwapExercise`) — БЕЗ зелёных обводок и заливок:**
- заливок ровно ДВЕ: выбранная строка — `--surface-pinned` (тот же светло-серый, что у закреплённой
  программы на главной), все прочие — `--color-card`. Рамки нет; «что выбрано» показывает ТОЛЬКО
  точка радио справа (зелёная обводка строки убрана — строка списка не должна кричать ярче кнопки
  действия);
- строка «от программы» ничем не залита и не обведена — у неё **бейдж «ОТ ПРОГРАММЫ» в правом ВЕРХНЕМ
  углу** (`position:absolute`, по 16px от верха и правого края — вровень с отступом до кружка радио).
  Название держит под него полосу (`BADGE_GUTTER`), иначе текст заезжает под бейдж.

**Грабля (бегущая обводка `SwapAnimationOverlay`).** SVG-контур строится по РЕАЛЬНОМУ размеру
карточки (`getBoundingClientRect` в `useLayoutEffect` → `viewBox="0 0 W H"`). Фикс-сетка 700×150 +
`preserveAspectRatio="none"` тянула картинку по осям неравномерно, и углы радиуса 33 превращались в
эллипсы — линия шла по скруглениям не по форме карточки. Любой контур поверх элемента — только по
измеренному размеру, без растягивания.

**Вариант в пикере (`ExercisePicker.jsx`):** та же карточка, справа круглая кнопка `+/✓` (см. «Икон-кнопки»).

**Вариант в конструкторе (`ProgramConstructor.jsx`):** та же карточка + drag-ручка вынесена **за** карточку
в левый жёлоб (чтобы превью стояло от края, как в эталоне), справа крестик удаления:
- Внешняя обёртка `exRowWrap`: `flex; alignItems:center; gap:6px`.
- Внутри — ручка (`width:28px; alignSelf:stretch; touchAction:none; cursor:grab`, глиф — inline-SVG)
  + сама карточка (`flex:1`).
- Перетаскивание — **простой transform-сдвиг** на pointer-событиях, без сторонних библиотек. Сознательно
  откатились сюда: версии с живой сортировкой (клон + FLIP/WAAPI + своп) дребезжали/лагали, Дмитрий
  попросил вернуть эту — плавную. Как работает:
  - Захваченная строка сдвигается `transform: translateY(dy) scale(1.03)` (за пальцем), соседи между
    стартом и целью разъезжаются на `±stride` через CSS-`transition` (`rowDragStyle`). `stride =
    offsetHeight + 10` (высота строки + gap списка). Цель = `startIndex + Math.round(dy/stride)`.
    Порядок применяется **на отпускании** (`moveItem`), не на лету. Строки держим по `rowRefs[idx]`.
  - `dy` включает **сдвиг скролла**: `(pointerY−startY) + (scrollY−startScrollY)`. Это позволило вернуть
    **авто-скролл** (`startAutoScroll`, rAF): палец у верх/низ края (`EDGE_TOP_PX`/`EDGE_BOTTOM_PX`) →
    `window.scrollBy`, и `applyDrag` пересчитывает — карточка остаётся у пальца, цель сдвигается. Авто-
    скролл тут НЕ дёргается (нет `getBoundingClientRect`/живого реордера — только арифметика + transition).
  - Группировка в это НЕ вмешивается: заголовки секций при drag статичны. Через границу группы мелкая
    неточность («заголовок чуть мозги делает») — мирятся ради плавности; внутри группы пиксель-в-пиксель.
  - Список рендерится секциями (`daySections` → `daySection` + `sectionRows`), gap внутри секции `10px`
    (= stride), между секциями `20px`. Без клонов/порталов/WAAPI — отсюда и плавность.
- **Кнопка «Добавить упражнения» — в потоке** (последним элементом списка, под последним упражнением /
  под подсказкой «Пусто…» у пустого дня), а НЕ прибита к низу. Внизу в доке остаётся только
  «Сохранить программу». При лимите (10/10) тап даёт тот же тост. Низ страницы (`paddingBottom`) держит
  место под док, чтобы кнопка прокручивалась выше него.


## Активное состояние без заливки

Активность/выбор показываем акцентом (цвет + размер), а не яркой заливкой фона.
Фон элементов остаётся нейтральным серым, активный отличается цветом `--color-primary` и/или
чуть большим размером. Примеры: выбор кол-ва дней в конструкторе (активная цифра зелёная и крупнее,
фон всех боксов одинаковый серый); кнопка `✓` в пикере (зелёный значок, а не зелёная заливка).


## Кнопка дока (нижнее основное действие)

Full-width кнопка внизу экрана («Добавить упражнения» в пикере/конструкторе):
`padding: 18px`, `borderRadius: var(--radius-card)`, dashed-рамка `1.5px rgba(255,255,255,0.18)`,
фон `rgba(34,34,34,0.55)` + `backdrop-filter: blur(12px)`, текст `13px / 700`. Обязательно `.press-tile`.
Док — `position:fixed`, фон-градиент к низу (`linear-gradient(180deg, rgba(13,12,12,0) 0%,
rgba(13,12,12,0.85) 40%, var(--color-bg) 85%)`), отступ от края `calc(16px + env(safe-area-inset-bottom))`,
`pointer-events:none` на контейнере + `auto` на кнопках. На страницах с прибитой кнопкой таб-бара нет —
гасить глобальный нижний скрим: `document.body.classList.add('hide-app-scrim')` на маунте.
Прятать кнопку при открытой клавиатуре (visualViewport, порог 150px), чтобы не липла к клавишам.


## ActionButton — общий компонент кнопки-действия (`components/ActionButton.jsx`)

Единая кнопка для всех основных «прибитых» действий. Рамка СПЛОШНАЯ (пунктир оставлен только
кнопке «Добавить упражнение» в конструкторе/пикере — там постоянно редактируем).
`<ActionButton variant disabled hug onClick style>…</ActionButton>`. Варианты:
- **dim** (всегда при `disabled`) — прозрачный фон `rgba(34,34,34,0.30)` + `blur(8px)`, текст тусклый,
  рамка `1.5px solid rgba(255,255,255,0.12)`. Это «неактивное» — не городить `opacity`.
- **neutral** — серая полупрозрачная `rgba(34,34,34,0.55)` + `blur(12px)`, рамка `…0.20`.
- **accent** — сплошная зелёная заливка `--color-primary` + чёрный текст `#0D0C0C`, рамка
  `1.5px --color-primary-dark`, БЕЗ блюра (обычная залитая кнопка). Цвет переопределяется через `style`
  (напр. «Завершить» заплыва — голубой `--cat-pool`). Это «готово/доступно». (Пробовали стеклянные
  варианты — цветное стекло и серую базу с цветным текстом — откатили к сплошной по просьбе Дмитрия.)
- **graphite** — сплошная графитовая заливка `--cat-gym` (#8B929C, цвет раздела Силовая) + тёмный
  текст `#0D0C0C`, рамка `1.5px rgba(0,0,0,0.18)`. Только кнопка **«Начать»** в дне тренировки
  (`WorkoutDay`): старт силовой = графит, а не зелёный (зелёный бережём под «готово»). Морф
  «Начать»→«Завершить» остаётся (графит → neutral → accent-зелёный с ✓ на 100%).
- **gray** — сплошная светло-серая заливка `--neutral-600` (#56575B) + **БЕЛЫЙ** текст
  (`--color-text`), тонкая светлая рамка `1.5px rgba(255,255,255,0.14)`. Нейтральные действия БЕЗ
  фирменного зелёного: «Добавить/Пригласить друга», «Сохранить программу» (конструктор + модалка
  друга), «Сменить упражнение». Иконку слева красить в белый (`color="var(--color-text)"`).
- **ghost** — прозрачный фон + тонкая рамка `1.5px rgba(255,255,255,0.14)` + приглушённый текст
  (`--color-text-secondary`). Вторичное действие рядом с основным: «Назад»/«Отмена»/«Открепить» в модалках.
- **primary** — ГЛАВНЫЙ CTA: сплошная зелёная заливка `--color-primary` + **БЕЛЫЙ** текст, БЕЗ обводки.
  Кнопка **«Начать»** ВЕЗДЕ (карточка программы на главной — там это `ctaPill`, а не ActionButton, но
  тот же вид; день тренировки; заплыв). Плей-иконка справа (`style={{gap:8}}`), регистр «Начать»
  (первая заглавная).

**ПРАВИЛО ЗЕЛЁНОГО CTA (Strava-принцип):** действие не перекрашиваем под контент. «Начать» — всегда
фирменный зелёный (`primary`) в любом разделе (силовая/плавание/кардио). Цвет раздела живёт на ИКОНКЕ и
ДАННЫХ (серо-стальная силовая, синее плавание…), а не на кнопке старта. «Завершить» (день + заплыв) —
фон прозрачный (`neutral`), но текст + флажок-иконка `FinishIcon` красятся `--color-primary`; пока
ничего не отжато — `opacity:0.55`, есть отмеченные — 1. Старый графит/зелёная-заливка-на-100% для
«Начать/Завершить» больше НЕ используются.
**Размер (проп `size`) — токенами, меняешь токен → меняется во всём аппе:**
- **`md`** (по умолчанию) — высота `--btn-height` (55), скругление `--radius-pill` (полная пилюля).
  Прибитые док-кнопки. Сюда же док «Добавить упражнения» (конструктор/пикер, но она пунктир, не
  ActionButton). (Таб-бар отдельно — 63.) На 55px радиус 33 и 90 визуально одинаковы (стадион), в коде 90.
- **`sm`** — высота `--btn-height-sm` (46), скругление `--radius-medium` (кнопки в модалках по правилу
  радиусов). Кнопки внутри модалок: `FinishConfirmModal` (Назад=ghost / Завершить=accent),
  `WorkoutFinishedModal` (ОК/Повторить=accent, ошибка — оранж-override), `SaveFriendProgramModal`
  (Сохранить=gray / Отмена=ghost), pin-модалка `Friends` (Закрепить=gray / Открепить=ghost). РАНЬШЕ это
  были инлайн-`<button>` с хардкод-радиусами 12/14/16 — свели к `ActionButton size="sm"`, теперь правятся
  централизованно.

Ширина: по умолчанию full-width; проп **`hug`** — по размеру контента (скругление облегает
текст), контейнер тогда центрирует (`display:flex; justify-content:center` или `alignItems:center`
у колонки-дока). Высоту/типографику переопределять через `style` (иконку слева — `style={{gap:8}}`
+ `<UiIcon color="#0D0C0C">`). **Все основные кнопки — `hug`** (так выглядит лучше): «Завершить»,
«Сменить» (SwapExercise), «Сохранить программу» и «Добавить упражнения» (конструктор/пикер; последняя —
пунктир, не ActionButton, но тоже hug), «Добавить друга»/«Пригласить друга» (Friends, gray). Любая
нажимаемая кнопка-действие — через него, а не инлайн. (Серые кнопки дисмисса инфо-попапов — `ModalButton`.)
- **Проп `progress` (0–100)** — заливка-прогресс за текстом (светло-серым, растёт по мере действия;
  обрезается по скруглению). Общий, но кнопка «Завершить» его СЕЙЧАС НЕ использует — прогресс дня
  показывает заливка шапки (`headerFill`, см. «Главная — шапка»). Кнопка «Завершить» — обычная hug:
  `neutral` до 100%, `accent` (зелёная, с ✓) на 100%.


## Заголовки над списками (`components/GroupLabel.jsx`)

Писались заново в каждом файле с разной разрядкой (0.2 / 1.5 / 1.6 / 2 / 3px). Два смысла:

- `<GroupLabel color={accent}>` — группа мышц/категория ВНУТРИ списка. **Цветная**:
  цвет здесь работает как навигация, глаз находит «Грудь» не читая.
- `<SectionLabel>` — секция экрана («Профиль», «Система»). **Всегда серая**: она
  структурирует экран, а не соревнуется с контентом. Проп `caps` — для лейблов формы
  («НАЗВАНИЕ», «МЕСТО»), разрядка одна на проект.

Хочется покрасить секцию — значит это на самом деле группа.


## Формы (`components/FormControls.jsx`)

`FormCard` (карточка-группа) + `ToggleRow` / `ValueRow` / `TextField` / `SelectRow`.
Правила: строка не ниже 56px; подпись под заголовком объясняет ПОСЛЕДСТВИЕ, а не
повторяет заголовок; разделитель между строками, не по краям; значение справа всегда
тише заголовка.

### Строка настроек — ОДНО правило на все экраны настроек

Строка: **заголовок слева обычным весом (`--weight-text`) — значение справа по ПРАВОМУ КРАЮ
и жирнее (`--weight-label`) — шеврон**. Все строки одного экрана обязаны быть одинаковыми: если
хоть у одной значение висит на середине (так было у поля «Рост» с инлайн-вводом), глаз теряет
вертикальную ось и перечитывает каждую строку заново.

- **Цвет значения:** данные — белым (`--color-text`); значение-ДЕЙСТВИЕ (строка ведёт куда-то,
  «Открыть») — акцентным. Зелёный в системе значит «нажми/происходит»; крася им рост и дату,
  мы обесцениваем сам сигнал.
- **Производная величина** (возраст рядом с датой) — проп `note`: приглушённая приставка к
  значению, **без скобок** (`03.12.1994  31 год`). Её не выбирают — её посчитали.
- **Разделитель** — волосок `--layer-2` ВНУТРИ строки, от левого паддинга карточки до правого
  края (`s.dividerLine`), а не рамка по краю: строки читаются списком, а не таблицей.
- **Кнопки «Сохранить» на экранах настроек НЕТ.** Значение уходит на сервер сразу после выбора,
  подтверждение — `haptic.success()`. Кнопка-индикатор («Сохранено» серым) — не работа кнопки:
  она весит больше самих данных и требует лишнего действия. Форма с «Сохранить» уместна там,
  где значений много и они связаны между собой.
- **Ввод с клавиатуры в настройках — крайний случай.** Клавиатура в мини-приложении дёргает
  весь экран (`visualViewport`), а руками можно занести рост 1930 см. Число из понятного
  диапазона выбирается барабаном (`WheelSheet`), а не набирается.
- **Лейбл секции не ставим, если секция на экране одна** — заголовок экрана уже всё сказал.

**Выбор без клавиатуры — `PickerRow`** (общая строка: заголовок слева, значение акцентом +
шеврон справа, тап открывает выбор). На ней собраны `SelectRow` (короткий список в `AnchorMenu`)
и пикеры-листы: **`WheelSheet`** — общий нижний лист с барабанами (`Wheel`, `scroll-snap`,
хаптика на переход с троттлингом 40мс, кнопка «Готово», тап мимо = отмена). На нём собраны
`BirthDateModal` (день · месяц · год, список дней пересобирается под месяц) и `HeightModal`
(один барабан, единица едет за выбранным числом). Новый выбор «покрути и подтверди» —
на `WheelSheet`, своих пикеров не писать.
Значение всегда одной строкой и одним цветом: «12.05.1990 (35 лет)» — возраст это расшифровка
даты, а не второй показатель, серым его не красить.

**Выбор из короткого списка — `SelectRow`, а не сегменты в строке** (сегментный `ChoiceRow`
убран 01.09.2026 вместе с последним его применением). Строка выглядит как остальные:
заголовок слева, значение справа акцентным (`--color-primary`) + шеврон; тап открывает тот же
`AnchorMenu`, что селектор раздела на главной (у выбранного пункта — галочка `ui:check`).
Ничего не выбрано — вместо значения приглашение «Выбрать» приглушённым, не прочерк: прочерк
не подсказывает, что строка нажимается. Сегменты оставляем для переключения ВИДА содержимого
(периоды, вкладки), а не для ввода данных о себе.

## PagerArrows — листание периодов (`components/PagerArrows.jsx`)

Стрелки «‹ ›» были свои в каждом месте и стояли ПО КРАЯМ строки (заголовок посередине). Свели в один
компонент и перенесли ОБЕ к правому краю строки — рядом они читаются как один переключатель, а
разнесённые заставляют искать вторую. Название периода при этом уезжает влево.

```jsx
<PagerArrows onPrev={} onNext={} canPrev={} canNext={} prevLabel="Раньше" nextLabel="Позже" />
```
Кружок 36px `--layer-2` + `ChevronIcon` (доворот `rotate(±90deg)`, свой глиф `‹`/`›` не рисуем),
хит-зона 44px, `.press-tile`, `haptic.selection()` внутри компонента. Недоступное направление гаснет
(`opacity 0.35`) и не тапается; заглушек вместо стрелок нет — ряд держит `minHeight: 44px`, поэтому
блок не прыгает, когда листать нечего. Применён в `WeightProgressModal` и `HistoryCalendar`
(единственные места листания периодов). Новое листание — только через него.


## ConfirmModal — единственная модалка «да / нет» (`components/ConfirmModal.jsx`)

Подтверждения были скопированы трижды (выход из конструктора, отмена силовой, отмена заплыва) и
в каждой копии выглядели по-своему: где пилюли, где прямоугольники с обводкой, где белая подпись.
Теперь один компонент — новые подтверждения только через него:

```jsx
<ConfirmModal
  title="Отменить тренировку?"
  text="Прогресс не сохранится и в историю не попадёт."
  onClose={close}                                   // = «остаться», тап мимо
  actions={[{ label: 'Нет', onClick }, { label: 'Да, отменить', onClick, danger: true }]}
/>
```
Правила внутри: заголовок белым (`--text-title-size`/800), пояснение под ним — **СЕРЫМ**
(`--color-text-secondary`; главный текст в модалке один), действия — серые пилюли `ModalButton`
**без обводки**, отклик = подсветка фона при удержании (без scale, как в нативном алерте iOS).
Деструктив красит ТОЛЬКО текст (`danger` → `--color-error`), заливка у всех кнопок общая. Портал и
заморозка фона — внутри компонента. Ширина одна на все подтверждения (360).


## ModalButton — серая кнопка для модалок/диалогов (`components/ModalButton.jsx`)

Нативный серый стиль (как кнопки iOS-алерта «Понятно/ОК/Отмена»), НЕ акцентный — для дисмисса
инфо-попапов и нейтральных выборов (в отличие от зелёной ActionButton accent для основных действий).
`borderRadius: --radius-pill` (полная пилюля), фон и подсветка нажатия — в классе `.modal-btn`
(index.css): база `rgba(255,255,255,0.13)`, `:active` ярче `0.22`, БЕЗ scale (как `.tg-row`).
Фон держим в CSS (не инлайн), иначе `:active` его не перебьёт. По умолчанию full-width; в ряд (две
кнопки) — обернуть в `display:flex; gap:10` и каждой `style={{flex:1}}`. Применяется: «ПОНЯТНО» в
инфо-попапах (разделы `CategoryInfoModal`), пара [Не сохранять][Сохранить] в
модалке выхода из конструктора. Кнопки «Понятно/ОК/Отмена» — больше НЕ ярко-зелёные.


## Лимит-индикатор (красный, при недопустимом действии)

Красное сообщение про лимит + шейк + `haptic.error()`. Два размещения под разный UX:

- **Пузырёк у элемента** — когда действие построчное (пикер: тап `+` на затемнённой строке сверх лимита).
  Пузырёк рисуется в строке слева от кнопки, ровно напротив неё: обёртка кнопки `position:relative`,
  пузырёк `position:absolute; right: calc(100% + 10px); top:0; bottom:0; display:flex; alignItems:center`
  (высота = высота кнопки → центр совпадает). Текст короткий («Лимит 10/10»), `radius-small`, blur-фон.
  Затемнение строки вешать на содержимое (превью/контент/кнопку), НЕ на всю строку — иначе пузырёк
  тоже приглушится; он должен оставаться ярким.
- **Центр-попап у дока** — когда кнопка одна общая (конструктор: тап «Добавить» при забитом дне).
  `position:fixed`, по центру над доком, `maxWidth ~200px` → текст в 2 строки, `radius-medium`, blur-фон.

Общее: хранить не булев флаг, а id/нонс, чтобы шейк перезапускался на каждый тап (`key={nonce}`).


## Заголовок экрана (ScreenTitle) — единый для всех экранов

Заголовок любого экрана — компонент **`ScreenTitle`** (`components/ScreenTitle.jsx`): стиль навбара
iOS/Telegram — `--font-manrope`, **18px, вес 600, БЕЗ капса** (sentence case), по центру, приглушённый
белый `rgba(255,255,255,0.9)`. Размер/вес/цвет правятся в одном месте (компоненте) — сразу на всех экранах.
Применён везде (Тренировки, Профиль, Друзья, Разделы, Избранное, История, Настройки,
Заплыв, Сменить упражнение, Своя программа…). Новый экран → заголовок через `ScreenTitle`.

**Это ФИКСИРОВАННЫЙ навбар, НЕ в потоке.** Рендерится `createPortal` в `document.body` как
`position:fixed`-полоса по центру системных кнопок Telegram (Назад / …) — заголовок встаёт в одну линию
с ними. Позиция из переменных `--tg-nav-top` (=`safeAreaInset.top`) и `--tg-nav-height`
(=`contentSafeAreaInset.top`), их задаёт `bindSafeArea()` (фолбэк в `index.css`). Портал ОБЯЗАТЕЛЕН:
`.page-enter/.page-fade` оставляют `transform` (fill-mode `both`) → создавали бы контейнер для `fixed` и
сбивали позицию. `zIndex:90` (ниже OfflineBanner 9998 — при оффлайне пилюля перекрывает заголовок, это ок).
Из потока заголовок ВЫНЕСЕН → контент экрана начинается ровно на 16px ниже кнопок (`paddingTop:
var(--tg-safe-top)` у `.page`), БЕЗ строки под заголовок и БЕЗ своего верхнего margin у первого элемента.
Иконки/сабтайтлы/боковые кнопки (кубок, ⓘ, шестерёнка, сердечко) идут первой строкой контента, НЕ в
строке заголовка. `style`-проп компонент больше не принимает (позиция фиксированная).

## Аватар — общий компонент `Avatar`, буква ВСЕГДА под фото

Один вид и одно поведение везде: своя карточка профиля, строка друга, модалка
чужого профиля (она рисуется через `ProfileHeader`, отдельного кода нет).

```jsx
<Avatar src={photo_url} name={displayName} size={52} />
<Avatar src={user?.photo_url} name={displayName} size={104}
        radius="var(--radius-card)" letterSize="var(--text-hero-size)" letterWeight={800} />
```

**Буква нарисована всегда, фото лежит ПОВЕРХ и проявляется по `onLoad`.** Раньше
было «или фото, или буква», и пока картинка летела по сети, в квадрате не было
ничего — пустая серая плитка, потом рывком фото. Теперь пустого места нет ни в
одном кадре, а если фото не доехало (нет сети, ссылка протухла, `onError`) —
остаётся осмысленная буква. Вход по почте (фото нет вовсе) выглядит так же, как
у всех: буква на `--surface-raised`, цвет буквы — акцентный.

**Проявление играет только при ПЕРВОМ показе ссылки.** Модульный `Set` помнит
уже отрисованные URL — иначе фото мигало бы fade-ом на каждой перерисовке строки
при прокрутке списка друзей и при каждом возврате на экран.

**Почему аватарки НЕ кешируются в наш `media-cache`.** t.me / telegram.me отдают
их БЕЗ `Access-Control-Allow-Origin`, поэтому забрать картинку в blob через
`fetch` нельзя — браузер не отдаст данные (наш S3 CORS разрешает, потому ролики
и кешируются). Остаётся HTTP-кеш браузера, а Telegram ставит `max-age=3600` —
через час картинка перезапрашивается, отсюда и «серое на секунду». Полное
решение — качать фото при входе в наш S3 и хранить свою ссылку; тогда заработает
и оффлайн, и `immutable`. Пока НЕ сделано, `no-cors` + Cache API не помогают
(opaque-ответ нечитаем, без Service Worker он никуда не подставится).


## Длинный тег не лезет на цифру — `MarqueeTag`

Тег упражнения («Ноги — Квадрицепс») раньше был `nowrap` без ограничения и на
длинных подписях заезжал под цифру веса. Цифра тут главное, её ничем перекрывать
нельзя; переносить тег на вторую строку тоже неверно — пилюля в две строки
перестаёт читаться как один ярлык и ломает высоту карточки.

Решение: не влез — многоточие, а по ТАПУ по самому тегу текст прокатывается влево,
показывает хвост и возвращается (с `haptic.selection`). Тап — единственный
свободный жест: карточка занята открытием, долгое нажатие — меню, свайп — панель
действий. Влез целиком — тап проходит НАСКВОЗЬ на карточку и вибрации нет:
перехватывать «на всякий случай» значит делать часть карточки мёртвой зоной.

**Грабли, обе про измерения:**
1. Тегу обязателен `min-width: 0`. Как flex-item он иначе получает
   `min-width: auto` (= ширина текста целиком), и `max-width: 100%` его не
   удержит — `min-width` в CSS сильнее. Из-за этого тег и заезжал на вес.
2. Длину прокатки считать по ТРЕКУ (`track.scrollWidth - track.clientWidth`),
   а не по пилюле. `clientWidth` пилюли включает её горизонтальные паддинги, и
   текст недокатывался ровно на них — хвост так и оставался за кадром.

**По умолчанию тег НЕ интерактивен — только многоточие.** Прокатка включается
`interactive` и ровно в ОДНОМ месте: модалка долгого нажатия по упражнению
(`ExerciseActionMenu`).

Почему так. В списках карточка ловит долгое нажатие, и живой тег посреди неё эту
зону съедал: человек метил в упражнение, попадал в тег — меню не открывалось.
Читать длинную подпись целиком нужно не на бегу по списку, а когда упражнение
уже открыто; там прокатка ничему не мешает и находится ровно под рукой.

Это общее правило для любого нового места с тегом: **живой элемент внутри
карточки, у которой есть свой жест, отбирает у неё этот жест.** Прежде чем
делать что-то внутри карточки кликабельным, проверь, чем занята сама карточка.


## Счётчик «сколько из скольких» — `SlotsCount`

Кнопки «Добавить N/12» (конструктор программы, пикер упражнений) показывают счёт
через общий `SlotsCount`: **набранное — акцентом** (`--color-primary`), **знаменатель —
всегда серый** (`--color-text-secondary`). Ноль тоже серый: зелёному взяться неоткуда,
пока ничего не набрано. Смысл разделения — числитель это результат человека,
знаменатель лишь рамка.

Своих размеров шрифта компонент НЕ задаёт — наследует от кнопки, поэтому одинаково
садится и в `md`, и в `sm`. Внутри «N/12» зазора нет (одна дробь), а от текста слева
его отделяет `gap` самой кнопки (`--space-1`).

Состояние лимита — исключение: «Достигнут лимит 12/12» красится ЦЕЛИКОМ в
`--color-error`, без деления на цвета. Это «стоп», а не достижение.

## Поп-ап-подсказка к значку (`StreakInfoPopup`)

Бицепс недели показан и в профиле, и строкой на главной — пояснение к нему одно
и то же, поэтому оно компонент. Раньше жило вёрсткой внутри `ProfileHeader`,
а на главной его не было вовсе, хотя именно там человек впервые видит цифру
и не понимает, что она значит.

**Поверхность — та же, что у меню долгого нажатия** (`AnchorMenu`): `--surface-glass`
+ `--blur-glass` + волосок `1px var(--layer-2)` + `--shadow-modal`. Всё, что всплывает
над контентом, должно читаться одной поверхностью. Радиус при этом свой —
`--radius-medium` (поп-ап), а не `--radius-card` (меню): по правилу радиусов.
Оранжевой обводки в цвет серии здесь БОЛЬШЕ НЕТ — она объясняла связь с огоньком,
а огонька в проекте не осталось, и цветная рамка вокруг обычного пояснения
кричала без причины.

Правила, зашитые внутрь:
- компонент сам держит своё закрытие (тап мимо, Esc, автоскрытие 6с) — место
  вызова знает только «открыт/закрыт», и копии логики не расходятся;
- `anchorRef` обязателен: тап внутри якоря не считается «мимо», иначе повторный
  тап по значку закрывал бы и тут же открывал поп-ап заново;
- ширина `max-content` с `maxWidth: min(260px, 100vw - 32px)` — жёсткие 230px
  упирались в край на узких экранах;
- центрирование `align='center'` сделано полями, а НЕ `translateX(-50%)`:
  `transform` занят анимацией выезда, два правила боролись бы за одно свойство.

**Тапом открывается вся фраза, а не только значок.** На главной кнопка — строка
целиком: человек метит в надпись, а не прицельно в маленький значок.


## Жест «+1 мускул» при завершении (`BicepGesture`)

Компонент `BicepGesture` — фирменный бицепс (как на лоадере), качается ОДИН раз и застывает,
вокруг непрерывно летят гладкие зелёные искры-круги (НЕ пиксели). **«+1» не висит статично —
он улетает вверх и гаснет** (`bgPlusFly`, один прогон, 1:1 с `plusOneFly` лоадера).

**Порядок в `WorkoutFinishedModal` (эталон):** модалка появляется СРАЗУ и целиком
(`wfPanelIn` — scale 0.92 + подъём 10px, 0.32s `--ease-ios`), а жест играет УЖЕ ВНУТРИ неё
(панель — `overflow:hidden`, поэтому «+1» обрезается её краями и не вылетает наружу).
Отдельной фазы «сначала бицепс на фоне, потом панель» НЕТ — пробовали, читается как две сцены.
Закрытие по «ОК» — обратная микроанимация (`CLOSE_MS` 260) и только потом `onConfirm`.

**Переход подтверждение → завершение — одна сцена, без мигания.** `FinishConfirmModal` получает
проп `closing`: по «Завершить» уезжает ТОЛЬКО панель (`CONFIRM_EXIT_MS` 180), затемнение остаётся;
через этот таймаут `WorkoutDay` снимает подтверждение и ставит модалку завершения. У оверлея
завершения СВОЕГО fade-in НЕТ (иначе фон мигает на кадр) — анимируется только панель.

**Высота модалки фиксирована:** заметка о лимите занимает МЕСТО строки похвалы (не добавляется под
ней), обе строки — `minHeight 34`. Иначе панель прыгала, когда сервер отвечал «уже засчитано».
Жест опущен ниже (`gestureWrap`, отрицательный нижний margin) — сверху остаётся воздух, чтобы
улетающий «+1» не обрезался у самой кромки, а заголовок стоит ближе к бицепсу.
После «ОК» модалку НЕ снимаем перед `navigate('/')` — иначе на кадр мелькает список упражнений.

**Очередь появления блоков — канон для «данные приходят не сразу».** Данные модалки приезжают
двумя волнами: локальные (время, дистанция) — сразу; серия за неделю, возвращение и рекорды —
одним ответом `api_finish_workout` (украшения переехали внутрь неё, второго запроса больше нет).
Раньше волн было три и каждая въезжала сама по себе: значок недели молча прыгал 2→3, «Отличная работа!» моргала и сменялась заметкой о
лимите, блок рекордов вываливался в панель через секунду. Стало (`useRevealQueue` в
`WorkoutFinishedModal`):
- каркас (панель, жест, заголовок, кнопка) стоит с ПЕРВОГО кадра — ждать нечего;
- место под строку показателей зарезервировано (`statsSlot`, `minHeight 26`) — панель не прыгает;
- блок ВПЕРВЫЕ появляется уже готовым и с анимацией `blockPopIn` (вырос до 1.10 и сел на место —
  вход-версия `timerPulse`), а не подменяет показанные цифры;
- очередь: показатели (+ похвала/лимит той же волной) → возвращение → рекорды. Первый ждёт
  `FIRST_REVEAL_MS` 620мс (пока улетит «+1»; для оффлайна/ошибки — 0), каждый следующий —
  `REVEAL_STEP_MS` 520мс после предыдущего. Данные опоздали → блок встаёт сразу по приезде, но той
  же анимацией;
- ждём сервер молча `SKELETON_AFTER_MS` 450мс, дольше — в зарезервированной строке проступает
  скелетон. **Скелетон только под то, что ТОЧНО будет** (строка показателей). Под рекорды/
  возвращение скелетона нет: их может не быть вовсе, и заглушка обещала бы то, чего не случится.

**Витрина `/modal-demo`** (DEV) — все состояния модалки + тумблер «Как в жизни (задержки)»,
который эмулирует ответ сервера (900мс) и второй запрос (1800мс). Очередь проверяется только на
задержках — правишь хореографию, смотри там.

**Содержимое модалки (сверху вниз):** «Тренировка завершена» — обычный регистр, АКЦЕНТНЫЙ зелёный
(не капс, не белый) → **строка показателей в линию**: `[бицепс N]` (`WeeklyMuscle` + цифра, число
берётся по `USER_CHANGED`, поэтому строка и ждёт ответа сервера), `[750 м]` у плавания и
`[часы N мин]`; ОБА показателя
одним кеглем `--font-display` 800/17 (как счётчик серии на главной), единицы серым, часы серые →
«Отличная работа!» белым (у повтора за день — «Так держать!») → серым «Достигнут лимит — 1 силовая
в день. Эта тренировка в статистику не войдёт.» (только при повторе) → кнопка. Строки
«+1 тренировка за сегодня» и эмодзи нет. Зелёной обводки и свечения у панели НЕТ.
Паддинги компактные (16/20/18, gap 8), сцена жеста 124px.

**Лимит предупреждаем ДО, а не после.** Тап «Начать» на второй тренировке ТОГО ЖЕ РАЗДЕЛА за день
(`hasWorkoutTodayOfType` из `utils/history` по московским суткам) открывает спокойную модалку:
«Сегодня силовая уже была. Лимит — 1 силовая в день. Вторая тренировка не попадёт в статистику и
серию» + «Отмена / Всё равно начать». Работает **во всех разделах** — и в дне силовой, и в заплыве
(там же и на автостарте по кружку Play). Раздел определяет `programCategoryKey(program)`, фразы
берутся готовыми из `categoryMetaByKey(key).limitTitle/limitUnit` (роды разные: «силовая была»,
«заплыв был») — не склеивать их из `label` на месте. Кнопку «Завершить» лимит НЕ запирает: активную
сессию всегда должно быть чем закрыть, иначе она повиснет навсегда.
Праздничную модалку завершения при этом НЕ меняем — там та же серая заметка про лимит.

**Экран под модалками завершения заморожен.** Три части: (1) `touchAction:'none'` +
`overscrollBehavior:'contain'` на оверлеях `FinishConfirmModal` и `WorkoutFinishedModal`
(body НЕ фиксируем — ломает закреплённую шапку); (2) в `WorkoutDay` `collapseTarget` держит
пилюлю, пока `showFinishedModal` — иначе после сохранения `isThisActive` гаснет, шапка
разворачивается и страница уезжает; (3) сторож скролла в `WorkoutDay` возвращает позицию, если
её сдвинуло изменение вёрстки.

На error/offline — обычная иконка (⚠️/📵), без жеста и без задержки (панель сразу).
Никакой «валюты» не копится — ни очков, ни мускулов: «+1» означает «+1 тренировка»
(недельная серия + счётчики статистики), лимит силовой — 1/сутки. Плавание и силовая
показывают ОДНУ И ТУ ЖЕ модалку `WorkoutFinishedModal`, разница только в пропсах.




## ModalShell — оболочка модального окна (`components/ModalShell.jsx`)

Каркас всплывающего окна: портал в `document.body`, скрим `--overlay-scrim`
с блюром, `--z-modal`, **заморозка фона через `useScrollLock`**, закрытие тапом
мимо окна (по самому окну — `stopPropagation`).

Заводить новое окно ТОЛЬКО через неё. Раньше каждое собирало каркас само —
четырнадцать мест, и в двух заморозку забыли: под открытой модалкой ехал фон.
Баг ищут долго, а причина одна — правило соблюдалось руками.

```jsx
<ModalShell onClose={close} align="center|bottom" contentStyle={styles.card}>
  …содержимое…
</ModalShell>
```

**Вид окон сюда НЕ сводить.** Подтверждение, барабан, календарь и лист
упражнений выглядят по-разному намеренно; общий здесь только каркас.
Не всё с `position: fixed` — модалка: прозрачная ловушка тапа под меню, тост
и панель кнопок конструктора порталом пользуются, а заморозка им не нужна.

## SegmentedControl — пилюля-переключатель (`components/SegmentedControl.jsx`)

Один на проект. Принимает произвольные `items` (`[{ id, label }]`), `value`,
`onChange`, `compact`. Активный сегмент залит `--color-surface-active` и подписан
акцентом.

Назывался `PeriodSwitcher`, и из-за узкого имени такую же пилюлю рисовали заново
ещё в семи местах (место тренировки, длина бассейна, режим пикера, дни
конструктора). Одна из копий уже разъезжалась: в конструкторе контейнер
рассыпался, сегменты становились голыми кнопками. Новый переключатель —
собирать здесь, а не копировать вид.

## Toast — короткое сообщение поверх содержимого (`components/Toast.jsx`)

Тоны по смыслу: `error` (недопустимое действие, лимит) · `offline` (сохранено
локально, оранжевый, мягче ошибки) · `neutral`. Проп `shake` подрагивает плашку
при появлении — для повторного тапа по заблокированному действию: человек уже
видел текст, и надо показать, что система ответила, а не молчит. Дрожь
перезапускается сменой `key` (см. `startBlockNonce` в `WorkoutDay`).

Появился из дубля: плашка «Сначала заверши тренировку» была скопирована слово
в слово в день силовой и в заплыв.

**Полоски прогресса компонентом НЕ заводим** — в дне записано «весь прогресс
дня — тут, а не полоской»: это осознанный отказ, а не пробел.
