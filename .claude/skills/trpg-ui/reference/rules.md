# TRPG UI — правила и грабли

Частные правила, на которые уже наступали. Ядро — в `SKILL.md`.

## Figma дизайн-система (зеркало токенов) — ДЕРЖАТЬ В СИНКЕ

Дмитрий дублирует дизайн-систему в Figma (файл **TRPG**, через локальный мост TalkToFigma).
Токены там — **Variables**, структура зеркалит `index.css` 1:1. Коллекции:
- **Primitives** (палитра, тип Color): группы `neutral/{0,500,600,850,900,950}`, `green/{400,500,700}`,
  `blue/{400,500}`, `orange/500`, `red/500`, `purple/500`, `pink/500`, `yellow/500`.
- **Semantic** (тип Color, ссылается на Primitives): группы `base/*`, `cat/*`, `tag/*`, `status/*`,
  плюс полупрозрачные с вшитой альфой (БЕЗ алиаса): `surface/dim` ↔ `--color-surface-dim`,
  `border/default` ↔ `--color-border`.
- **Radius** (Number): `card=33, medium=20, small=10`. **Size** (Number): `tabbar-height=72, tabbar-bottom=16`.

**Соответствие имён** (детерминированное): Figma `green/500` ↔ CSS `--green-500`;
`base/primary` ↔ `--color-primary`; `cat/strength` ↔ `--cat-strength`; `Radius card` ↔ `--radius-card`.
Группа через `/` в Figma = дефис-префикс в CSS.

**ПРАВИЛО СИНКА (обязательно):** любое изменение токена в `index.css` (новый цвет, смена hex
примитива, перепривязка семантики, новый радиус) → **в конце ответа напомнить Дмитрию продублировать
это в Figma**, с точной инструкцией: коллекция → имя переменной → новое значение/ссылка.
Пример напоминания:
> 🎨 Синхронизируй Figma: Primitives → `green/500` → значение `#8FC04A` (было `#9ED153`).

И наоборот: Дмитрий меняет Variables в Figma → присылает (скрин/ссылку на узел) → переносим в код.
Читать переменные через мост: значения видны на узле, но привязку «это Variable» он не отдаёт —
сверять по скрину панели Variables или по залитому узлу.


## Мгновенный рендер страниц — без мигания (stale-while-revalidate)

Канон переключения между страницами: контент открывается СРАЗУ своими данными, фон догоняет.
Никаких «Загрузка…»-текстов и пустых заглушек до загрузки.
- Данные страницы иметь в **синхронном кеше**: память (`lib/cache`) + **персист в `localStorage`**
  (память теряется при перезапуске Telegram-вебвью — тогда localStorage даёт мгновенный старт).
  Примеры: `getRecentWorkoutsSync`, `getFriendsListSync`, `getFavoritesSync` (память → localStorage → null).
- Стартовый `useState(() => getXxxSync() || …)`, в `useEffect` — асинхронный `getXxx()` обновляет.
- Пустую заглушку (типа «сделай первую тренировку») показывать ТОЛЬКО когда реально загружено и
  пусто; пока грузится (кеша нет, первый заход) — **скелетон**, не заглушку и не «Загрузка».
- Прогрев кешей после логина — в `App.jsx` (история/друзья/любимые), чтобы первый заход был готов.
- Фото (`photo_url`) держать в кешированном юзере/списке — тег `<img>` рендерится сразу, браузер
  докеширует картинку; серый плейсхолдер — только контейнер под фото, не пустой экран.


## «Скоро» = не готов БЭКЕНД, а не «нет экрана»

Если у пункта есть `path` — он открывается, даже с меткой «Скоро». Мёртвая строка,
которая ничего не делает, хуже страницы, объясняющей что будет. Экран при этом честно
пишет, что сохранение/отправка ещё подключается (`SoonNote`).


## Пользовательский контент

Контент, который вводит юзер (название своей программы), показываем **как есть** — не нормализовать
регистр. `toLowerCase()`-нормализация («Первая заглавная, остальные строчные») — только для встроенного
контента. Развилка по `source === 'custom'`. Кастомной программе — свой акцент: тег зелёный (`--color-primary`).
Это правило действует **везде**, где выводится имя программы: карточки (Home, Category), карусель
избранного И **история** (`describeWorkout` в `utils/history.js`) — частая грабля: история гнала всё
через `titleCase` и ломала регистр кастомных имён.


## Telegram Mini App

- **Хаптика** — через `haptic` из `src/lib/telegram.js`. Методы: `light/medium/heavy/soft/rigid`
  (impact), `success/warning/error` (notification), `selection`. Раскладка:
  `haptic.light()` — обычный тап, `haptic.medium()` — long-press,
  `haptic.success()` — сохранение/успех, `haptic.error()` — недопустимое действие (в паре с `.shake-error`),
  `haptic.selection()` — микро-интеракции (фокус поиска, очистка поля, переключение чипов/сегментов,
  шаг перетаскивания, **переход подсветки с пункта на пункт при выборе протяжкой**).
  Любой интерактив — с хаптикой.
- **Ведёшь палец по чему-то выделяемому — каждая граница должна отзываться.** В меню долгого
  нажатия (`AnchorMenu`: программы, друзья, упражнения) палец, не отрываясь, ведёт
  по пунктам, и на КАЖДОМ переходе подсветки идёт `haptic.selection()` — как в нативных меню
  iOS и в самом Telegram. Правила: отклик ровно один на переход (сравнение хранить в `ref`,
  не в состоянии — `setState` асинхронный и в dev прогоняется дважды); уход в пустоту мимо
  пунктов МОЛЧИТ (вибрация значит «под пальцем есть что выбрать»); повторное движение внутри
  того же пункта молчит. Заводишь новый список с выбором протяжкой — повторяй этот рисунок.
- **Safe area** — `--tg-safe-top` (фолбэк 116px, перезаписывается реальным из `bindSafeArea()` =
  `sys+ui+8`). Также `bindSafeArea` задаёт `--tg-nav-top`=`sys` (вырез) и `--tg-nav-height`=`ui`
  (полоса кнопок Telegram) — по ним позиционируется фиксированный `ScreenTitle` (см. «Заголовок экрана»).
  Таб-бар: `--tabbar-height` **63px** + `--tabbar-bottom` 16px. Контент страниц — класс `.page`.
- **Краевой скрим** — `.app::before` (верх, под навбаром-заголовком) и `.app::after` (низ, над
  таб-баром): один рецепт градиент `var(--color-bg)→transparent` + `blur(3px)` + маска (гаснет без
  линии), `position:fixed`, `z:90`. Верхний высотой `calc(safe-top+16px)`, **нижний — в 2 раза ниже
  верхнего: `calc(var(--tg-safe-top) / 2)`** (по просьбе; верхний не трогать). Блюрит контент за собой
  при скролле; заголовок навбара (`z:95`) и таб-бар (`z:100`) выше — остаются резкими. `.app::after`
  гасится на конструкторе (`body.hide-app-scrim`) и при клавиатуре; `.app::before` — всегда.
  Верхний `.app::before` чуть ниже (`height: calc(safe-top + 16px)`, маска до 65%) — текст под
  заголовком при скролле мутный/тёмный, сам заголовок (`z:95`) резкий.
- **Скрим ПОД закреплённой шапкой — единый токен `--scrim-sticky`** (чтобы контент «нырял» под шапку):
  `linear-gradient(to bottom, rgba(10,10,10,0.95) 0%, rgba(10,10,10,0.6) 50%, transparent 100%)`, высоту
  (16–24px, сейчас 24) задаёт элемент, БЕЗ блюра/маски — простой градиент, легко подстраивать. Один
  на всё: день тренировки (`WorkoutDay.stickyFade`), главная под избранным (`Home.stickyFade`), пикер
  упражнений (`ExercisePicker.topFade`). Старый вариант (градиент к `--color-bg` + `blur(3px)` + mask) убран.
- **`.dock-scrim`** — тот же рецепт для экранов со своими прибитыми доками, где `.app::after`
  скрыт (день/конструктор/пикер/смена). Это отдельный `<div className="dock-scrim" />` ПЕРВЫМ
  ребёнком дока (`position:absolute; inset:0; z-index:-1`) — блюрит контент за доком, но маска НЕ
  режет кнопки (они выше по слою). У дока убрать свой `background`-градиент; если док не fixed/з-
  индексный (пикер) — задать ему `z-index`, чтобы `z:-1` лёг внутри него, а не за списком.
- **Клавиатура iOS** — высоту ловить через `visualViewport` (прятать док при открытии, показывать
  с задержкой ~350мс при закрытии, чтобы возврат не попал в анимацию клавиатуры).
- **Тема** — `color-scheme: dark`, тёмная. Проект тёмный by design.


## Цвет метрик — ДВА правила, по смыслу цвета

Одного правила «всё одним цветом» или «только цифра» не бывает — выбор зависит от того, что цвет
СООБЩАЕТ. Тест: «поменяется ли смысл, если сменить цвет?»

- **Цвет-ВАЖНОСТЬ** (обычная метрика: «6 трен», «750 м», «3 упр») — цвет лишь выделяет главное.
  Красим ТОЛЬКО число (`--color-primary`), иконку и единицу оставляем серыми. Иначе строка
  превращается в цветную кашу и иерархия внутри неё пропадает.
- **Цвет-СИГНАЛ** (длительность тренировки: зелёный → оранжевый → красный = уложился/затянул/
  перебрал) — цвет и есть сообщение. Красим ГРУППУ ЦЕЛИКОМ: часы, число и единицу. Покрасить одну
  цифру = глаз прочитает её как «важное число», а не как предупреждение; сигнал работает только
  цельным пятном.

Светофор применяется ИСКЛЮЧИТЕЛЬНО к длительности тренировки (`workoutTimerColor`). Время суток
(«12:37» — когда тренировка была) — просто факт, всегда серое. Действует везде: модалка финиша,
детали дня в календаре, шапка дня.


## Свои упражнения — правило на ЛЮБУЮ правку списков упражнений

В приложении два источника упражнений: каталог приложения и то, что человек завёл
сам (`ux_*`, см. скил trpg-supabase). **В интерфейсе они не должны выглядеть
разными сущностями.** Карточка та же, высота та же, вес и история работают так же.
Отличий ровно два, и оба — опознавательные, а не структурные:

- **карандаш** серым сразу после названия (`PencilIcon size={12–13}`) — «это завёл
  ты, это можно править». В каталоге карандаша нет вовсе, поэтому «своё» видно
  с одного взгляда, не читая;
- **цвет тега**: выбрал существующую группу — цвет этой группы, своё встаёт
  в общий строй; придумал свою («Кроссфит») — акцентный приглушённый
  (`getMuscleGroupColors(group, /* custom */ true)`). Серый фолбэк тут читался бы
  как «сломанная группа».

Правя любой список упражнений, прогоняй оба: `isCustomExercise(id)` → карандаш
и вторым аргументом в `getMuscleGroupColors`. Места, где это уже учтено: карточка
дня, конструктор, быстрый режим, пикер, любимые (страница и профиль), меню долгого
нажатия, шапка экрана техники.

**«Замены» у своего упражнения нет** — подбирать не из чего, экран открылся бы
пустым. Действие убрано из свайпа при `slot.is_custom`.


## Заведение своего упражнения — в пикере, не в профиле (`ExercisePicker`)

Вкладки «Все упражнения | Мои» тем же сегмент-контролом, что «Все / Быстрый режим»
в конструкторе. Кнопка «Создать упражнение» — первой строкой списка и ростом
с карточку (90px): это элемент списка, а не служебная мелочь под ним.

Заведение живёт именно здесь по одной причине: нужда в своём упражнении возникает
ровно в момент сборки дня — «нужного нет». Отдельный пункт в профиле заставил бы
уйти с экрана, создать, вернуться и заново найти место — лишний экран ломает
главный сценарий ради аккуратности меню.

В «Моих» поиска и фильтр-чипов нет: там максимум дюжина карточек, фильтровать
нечего. Долгое нажатие → `AnchorMenu` «Редактировать / Удалить» — тот же жест
и то же меню, что у программы на главной и у строки друга (допуск на смещение
пальца 10px обязателен, иначе на удержании меню не открывается).

Форма (`CustomExerciseForm`): обязательно только название. Группу и подгруппу
человек ПИШЕТ сам — он заводит упражнение как раз потому, что нужного в каталоге
нет, и заставлять его в этот момент подбирать чужую классификацию значит ставить
лишнее решение не вовремя. Выбор из готовых групп рядом, кнопкой-стрелкой, и он
не про порядок в данных, а про ЦВЕТ тега. Сверху — живой предпросмотр карточки:
человек видит результат, а не поля. Загрузки картинок нет, всегда placeholder.


## Многоточие не должно оплачиваться обрезкой букв

`textOverflow: ellipsis` работает только в паре с `overflow: hidden`, а тот режет
ВСЁ, что вышло за строку, — включая хвосты `р`, `у`, `д`, `p`, `g`, `q`. Если
`lineHeight` тесный, многоточие получается ценой обрезанных букв.

Так поймали имя в профиле: `--text-heading-size` (22px) при `lineHeight: 1.1` —
у «Rpgdpg» срезало низ обеих `g`. Лечится высотой строки, а не паддингом:
**1.3 для 22px**. Меньше 1.25 при наличии `overflow: hidden` не ставить.

Проверять на слове С ВЫНОСНЫМ ЭЛЕМЕНТОМ («Упражнения», «Rpgdpg»), а не на
«Профиль» — на словах без хвостов дефект не виден вовсе.

Заголовок экрана (`ScreenTitle`, 18px/1.2) оставлен как есть намеренно: хвосты
там стоят впритык, но не режутся, а высота строки завязана на позиционирование
фиксированного навбара по кнопкам Telegram — трогать дороже, чем польза.


## «Любимые»: короткий тап ничего не открывает

Рабочих действий на экране ровно два — поправить вес (тап по цифре) и прочитать
длинный тег (тап по нему). Меню — только долгим нажатием, как у программы
на главной и у строки друга. Раньше короткий тап открывал меню, и любая попытка
тронуть вес мимо цифры выкидывала в модалку.


## Единица измерения своего упражнения — кг или раз

Та же настройка, что делит каталог на «жим 80 кг» и «подтягивания 12 раз»
(`counts_reps`). Выбирается в форме своего упражнения сегментом, показывается
подписью под цифрой в карточке дня, меню долгого нажатия и любимых. Ничего
отдельного под свои упражнения не заводилось — колонка уже была.


## Клавиатура забирает первый тап

Открыта клавиатура (или закрылась < 350мс назад) — тап по фильтру/вкладке ТОЛЬКО
убирает клавиатуру, само действие не выполняется. Иначе промах мимо поля разом
и закрывал клавиатуру, и менял фильтр, которого человек не просил. Тот же приём
уже стоит в `ExerciseActionMenu` (там про вес и заметку).


## День опустел — состояние с выходом, а не серая строка

Удалил своё упражнение — оно ушло из всех программ, где стояло, и день мог
остаться пустым. Это не ошибка и не «данные не загрузились», поэтому `EmptyState`
с заголовком-фактом и кнопкой «Открыть конструктор» (у своей программы).
Прежняя сухая строка «День пуст — упражнения не настроены» читалась как поломка.
