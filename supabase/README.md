# База данных TRPG

## Файлы

| Файл | Что это | Когда меняется |
|---|---|---|
| `schema.sql` | **Полная структура базы.** Одна актуальная версия, перезаписывается целиком | после каждой правки базы |
| `seed.sql` | Справочные данные: каталог упражнений, встроенные программы | когда меняется каталог |
| `migrations/` | Пустая. Понадобится, когда появятся живые пользователи (см. ниже) | — |
| `functions/` | Edge Functions (сейчас одна — `telegram-auth`) | — |

## Правило: в гите ОДНА актуальная версия

Не копим десяток файлов со слоями правок. После любого изменения базы
`schema.sql` пересобирается заново и перезаписывается — в репозитории всегда
ровно один файл, описывающий базу такой, какая она есть сейчас.

История правок при этом не теряется: она в истории git. Посмотреть, что
менялось и когда:

```bash
git log -p supabase/schema.sql
```

Это работает, потому что **живых пользователей ещё нет** и базу можно
пересоздавать. Как только появятся реальные люди с данными — правило меняется,
см. следующий раздел.

## Развернуть базу с нуля

```bash
# 1. структура
psql "$DATABASE_URL" -f supabase/schema.sql
# 2. справочники
psql "$DATABASE_URL" -f supabase/seed.sql
```

Порядок обязателен: seed вставляет данные в таблицы, которые создаёт schema.

Локально то же самое делает `supabase start` (нужен Docker) — он сам поднимет
Postgres и применит оба файла.

Файл рассчитан на Supabase, а не на голый Postgres: `current_user_id()`
обращается к `auth.uid()` из GoTrue. Для self-hosted Supabase это работает без
изменений — там тот же GoTrue.

## Когда появятся живые пользователи

`schema.sql` пересоздаёт объекты, поэтому накатывать его на работающую базу с
данными будет нельзя. Тогда:

* каждая правка оформляется отдельным файлом в `migrations/` с меткой времени:
  `20260819143000_add_something.sql` (формат обязателен — Supabase CLI ищет
  именно его и по нему же понимает порядок применения);
* `schema.sql` продолжает жить как слепок для разворачивания с нуля и
  обновляется после каждой миграции;
* накопилось много миграций — их схлопывают в новый слепок, а папку чистят.

## Как менялась база

Полная история — в git. Крупные вехи:

* **2026-08-14** — свои упражнения пользователя (`exercises.owner_id`),
  копирование личных упражнений из программы друга.
* **2026-08-19** — ревью: удалены три функции, которые никто не вызывал,
  снята «валюта» отменённой игровой системы (мускулы, награды, ранг-бейджи),
  вычищены пустые колонки `programs` и дубли индексов.
