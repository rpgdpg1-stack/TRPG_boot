# TRPG — гайд для Claude Code

Фитнес-трекер, Telegram Mini App. Ставка на простоту и минимализм — игровые механики
(XP, лиги, ранги, награды, рейтинг) намеренно выпилены. Стек: Vite + React 18 +
React Router 6 + Supabase + Telegram WebApp SDK. Стили — CSS (НЕ Tailwind).
**Боевой хостинг — Timeweb** (домен `trpg1.ru`, туда смотрит Mini App в Telegram);
Vercel — запасной аэродром, а не основной.
Пользователь (Дмитрий) — нон-программист, общение на русском.

## Скилы и агенты проекта

**Скилы** (`.claude/skills/`) — знания и процедуры, подхватываются автоматически.
**trpg-workflow** — входная точка для любого запроса; из неё маршрутизация в остальные:

- **trpg-workflow** — рабочий процесс: как вести задачу, формат правок, коммиты+пуш,
  именование, грабли, добавление программ, обновление самих скилов.
- **trpg-ui** — дизайн-система: CSS-переменные, цвета, скругления, шрифты, отступы,
  press-эффекты, анимации, хаптика. Частности — в `trpg-ui/reference/`
  (`components.md`, `modals.md`, `screens.md`, `rules.md`), читать по необходимости.
- **trpg-supabase** — конвенции БД: схема, RPC, RLS, миграции, Edge Functions.
- **trpg-ds-review** — страж целостности ДС: звать ПЕРЕД правкой интерфейса
  (переиспользуй существующее, новое — только с обоснованием).
- **trpg-figma** — перенос и синк проекта в Figma через мост TalkToFigma.

**Агент** (`.claude/agents/`) — отдельный исполнитель со своим контекстом:

- **trpg-product-review** — UX-ревью экрана/флоу (сценарии, иерархия, понятность). Звать
  явно: `@agent-trpg-product-review`. Код не меняет, возвращает список правок.
  Не путать с `trpg-ds-review`: тот про токены и консистентность, этот про UX.

Плюс глобальный скил **skill-author** (уровень аккаунта) — по нему пишутся и
разбиваются сами скилы: ядро + `reference/`, куда дописывать, когда заводить новый.

## Коммиты + пуш

Дмитрий разрешил **авто-коммит и авто-push** в этом репо: после `npm run lint` + `npm run build`
(оба зелёные) коммит прямо в `main` (сообщение на русском, conventional commits) и сразу
`git push`. Ручное нажатие в GitHub Desktop не нужно. Проверка — на сайте GitHub; если что —
откат по просьбе.

## Context7 (актуальная документация библиотек) — экономно

Context7 — источник свежей официальной документации внешних библиотек/SDK/API. Использовать
**только когда правда нужно**, а не на каждом шаге (беречь токены).

**Когда вызывать:** новый код или интеграция с React, React Router, Vite, Supabase (client SDK,
RLS, auth, realtime), Telegram Mini Apps / Bot API, любым сторонним npm-пакетом — и когда важно
именно текущее поведение API (версии, устаревшие методы, breaking changes). Тянуть только нужный
кусок доки под задачу, не всю библиотеку.

**Когда НЕ вызывать:** UX/UI и продуктовые решения, ревью дизайна, архитектура, бизнес-логика,
чистый JS/TS без внешних API, рефакторинг без смены API библиотек.

**Ключевое правило (экономия):** если я уверен в API и свежие изменения вряд ли на него влияют —
Context7 НЕ дёргать, работать сразу. Вызывать только для проверки неуверенного или
version-sensitive поведения. Приоритет при расхождениях: доки Context7 → конвенции проекта →
знания модели; изменение по свежей доке — коротко пояснять.

**Ревью кода:** определить используемые библиотеки → по ним свериться с Context7 → сообщить
находки (устаревшие/неверные вызовы, breaking changes, лучшие паттерны) → править только после
согласования.

_Прим.: коннектор Context7 подключается как MCP-сервер в Claude Code (`claude mcp` / настройки).
Если он не подключён в сессии — эти правила ждут своего часа, вызвать его нельзя._

## Браузерные MCP (Playwright / Chrome DevTools) — автоматический выбор

Оба MCP подключены глобально (browser automation). Вызывать их **автоматически** под задачу, но
только когда от этого есть **реальная польза** — не запускать браузер ради самого запуска.

**Playwright MCP** (`mcp__playwright__*`) — действие в приложении. Вызывать автоматически для:
тестирования приложения, проверки UI, воспроизведения багов, валидации пользовательских
сценариев (открыть экран, кликнуть, заполнить форму, снять скриншот).
**НЕ вызывать**, когда запускать само приложение не нужно (обсуждение, правки кода без проверки в
UI, чистая логика/стили без визуального прогона).

**Chrome DevTools MCP** (`mcp__chrome-devtools__*`) — диагностика под капотом вкладки. Вызывать
автоматически для: браузерной диагностики, ошибок в консоли (console errors), сетевых запросов
(network requests), проблем производительности (performance), рендеринга или CSS.
**НЕ вызывать**, если браузерная инспекция не даёт явной пользы.

**Общее правило:** сам подбирай наиболее подходящий MCP-инструмент под задачу, но не дёргай его
без реальной пользы. Нужно *сделать* что-то в UI и проверить глазами → Playwright. Нужно
*диагностировать* (консоль / сеть / перф / рендер) → Chrome DevTools.
